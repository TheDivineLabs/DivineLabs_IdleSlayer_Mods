# DivineLabs Idle Slayer Design

Актуальный файл: https://www.figma.com/design/5Ml26SowEwW95efKkcCEda.
Страницы: `01 · Установщик`, `02 · Программа`, `90 · Архив`. В архиве
сохранены прежние PNG и редактируемые установочные экраны. Каталог разделов,
исходников и цветов: `docs/design/catalog.json`.

Настольные окна используют светлый фон #FAFBFE, белые карточки, текст #1B2638
и фиолетовый акцент #6658E8. `SetupTheme.xaml` задаёт элементы обслуживания,
`ApplicationTheme.xaml` — оболочку лаунчера. Мастер поддерживает русский и
английский языки: автоматический режим берёт CurrentUICulture, неизвестный
язык использует английский. Смена языка сохраняет этап, путь и принятие условий.
Тексты лицензий остаются оригинальными. Кнопка «Готово» закрывает мастер без
запуска; отмена до завершения требует подтверждения; замена файлов блокирует выход.

`scripts/design/Export-ProductDesign.ps1` собирает библиотеку под
`W:\DEV\artifacts\DivineLabs_IdleSlayer_Mods\DivineLabs Idle Slayer Design`:
`01 Установщик`, `02 Программа`, `03 Удалятор`, `Shared`. В каждом разделе
есть Screens и Editable; Shared содержит стили, исходники и брендовые материалы.
SVG получаются из расположенных WPF-элементов, сохраняют текст и векторы;
игровая обложка остаётся растровой. Импорт в Figma не связывает макет с кодом автоматически.

`scripts/design/Build-DesignPreview.ps1` собирает отдельный Setup EXE и portable
ZIP из проверенного комплекта компонентов. Это предварительный комплект дизайна,
а не новая стабильная версия. Текущая установка и опубликованный релиз не заменяются.
Игровой интерфейс в этом проходе не изменялся.

Окна имеют прямые внешние углы. Общая обработка `WM_GETMINMAXINFO` ограничивает
развёрнутое окно рабочей областью текущего монитора, чтобы нижние действия
оставались над панелью задач. Кнопки заголовка и стрелка языка используют
векторную геометрию. Наведение покрывает всю поверхность кнопки, а отдельная
рамка фокуса появляется только при клавиатурной навигации. Активные круги этапов
рисуются без дополнительной обводки; у лицензий постоянно видна дорожка прокрутки.

Меню языка закрывается повторным нажатием, нажатием снаружи, Escape и потерей
активности окна. Проверка этих обработчиков и фактической компоновки развёрнутого
HWND: `dotnet run --project tests/Layout/Layout.csproj -c Release -- <каталог> --window-check`.
Она отправляет WPF-события, сохраняет снимки и размеры окна; физический ввод
мышью, системные масштабы DPI и несколько мониторов требуют отдельной проверки.

## История интерфейса 0.4
Визуальный прототип: design/preview.html. Настольные окна используют DesktopUI/Theme.xaml; игровой интерфейс — uGUI/TMP и один девятисегментный спрайт скругления. Логотип в WPF — вектор, в Unity — тот же собственный векторный контур, однократно растеризованный при создании интерфейса. Цвета: фон #10141C, поверхность #1A2230, граница #303D50, акцент #72CFFF, текст #EEF2F8, вторичный текст #A4B0C2.

Главная содержит запуск и состояние. Функции содержат поиск, категории, избранное и независимые переключатели. Настройки содержат назначения, виджет и обслуживание. Пустой раздел автоматизаций не добавлен. Новая функция регистрируется в FeatureCatalog с постоянным идентификатором; её игровая реализация добавляется отдельно.

Меню по умолчанию — Insert. Кнопка виджета открывает меню. Для перемещения: Настройки → Переместить виджет → перетащить и отпустить. Клавиша меню отменяет режим перемещения. Координаты относительные, прозрачность 20–100%, масштаб 75–150%. Работа игры не приостанавливается.

Лаунчер и обслуживание используют одну автономную сборку WPF в разных процессах/режимах. NativeAOT Setup извлекает только App/Launcher из встроенного архива и запускает --maintenance. Операции выполняются отдельным NativeAOT worker; UI получает этапы и ждёт код завершения. При удалении установленный EXE сразу освобождается; UI и worker остаются во временной папке. Завершённая сессия помечается maintenance.complete и удаляется следующим запуском Setup. Рабочие и резервные данные пользователя не затрагиваются этой очисткой.

Состояние игры публикуется неизменяемыми снимками. SessionHost владеет .owner-файлом всю сессию; изменения сериализованы, проверяются по Revision и сохраняются до подтверждения. Pipe CurrentUserOnly, протокол 1, сообщения ограничены 64 КиБ, соединение ограничено по времени. Обработчик не вызывает Unity API; отображение обновляется на игровом потоке при смене ревизии. Лаунчер вне игры берёт ту же блокировку и повторно проверяет процесс.

Рендеры WPF создаются командой:
dotnet run --project tests/Layout/Layout.csproj -c Release -- W:\DEV\artifacts\DivineLabs_IdleSlayer_Mods\design-0.4

Они проверяют компоновку и ресурсы, но не заменяют физический ввод, поведение DPI Windows или игровые испытания.
## Установщик 0.4.1

По замечаниям владельца выбран светлый Fluent-интерфейс с портретной игровой
обложкой. Название окна и установочного EXE: DivineLabs Idle Slayer Mods.
Бренд пишется DivineLabs. Знак — плавная D из трёх частей по предоставленным
референсам; исходник assets/DivineLabs.svg. Иконка приложения сохраняет
оригинальный значок игры с небольшим бейджем DivineLabs.

Мастер: начало → лицензии → параметры → установка → готово. Удалятор:
начало → подтверждение папки → удаление → результат. Повторная установка
определяется по установленному EXE. Общие элементы используют Theme.xaml,
светлая палитра и элементы мастера — SetupTheme.xaml в DesktopUI.

Отчёт о прогрессе является необязательным каналом отображения: атомарная
замена через File.Replace, чтение с разрешением записи/удаления, устойчивость
к временной блокировке. Успех определяется кодом завершённого worker.
