# Ресурсы и покупки · ПК 0.5.0

Поддерживается локальная Steam-сборка 25810322, GameAssembly SHA256
AB968489DF8032A895898D9B90EE3E583F416D4FBC97C427D935EFA457BFB38A.
Технические выводы основаны на локальных методах и проверенных нативных вызовах.
Игровые DLL и извлечённые исходники не включаются в репозиторий.
Фактически выполненные проверки отдельно перечислены в VALIDATION.md.

## Разовая выдача

В лаунчере и игровом меню добавлен раздел «Ресурсы». При запущенной игре нужно
обновить баланс, выбрать ресурс, количество и нажать «Выдать». Материалы
выбираются из текущего игрового каталога; поиск работает по локализованному имени.
Команды исполняются на игровом потоке. До изменения создаётся копия файлов .sav
в UserData/DivineLabs.Backups/Resources. Автоматического отката сохранений нет.

| Ресурс | Реализация и границы |
|---|---|
| Монеты | Штатный AddCoins, обновляет текущий и пожизненный баланс. Множитель тренера повторно не применяется. |
| SP | Доступные Slayer Points и пожизненные SP увеличиваются согласованно. Накопленные до восхождения pre-SP сохраняются. Обновляется формула следующего USP. |
| DP | Увеличивается общий заработанный DP. Доступное количество игра вычисляет с учётом уже купленных божественностей. |
| USP | Увеличивается кошелёк, пересчитываются пожизненные очки и следующая стоимость. Число ограничено конечностью игровой формулы 600000 × 1.23^n. |
| Материалы | DropsManager.AddDrop без повторного удвоения и искусственного продвижения заданий. Сохраняется фактический лимит сумки. Выдача не обещает поддержку всех предметов вне списка drops. |
| Камни душ | Увеличиваются локальный баланс jewelsOfSoul и счётчик заработанных jewelsOfSoulEarned. Purchased, Purchases и список оплаченных транзакций не подделываются. |
| Фишки казино | Не добавлены: отдельные серверные GetPlayerData/SpendChips/BuyItem. Локальный текст баланса не подтверждает выдачу у сервера. |

Количество — целое конечное double от 1. Проверяются переполнение,
потеря малого начисления на большом балансе и зависимые игровые формулы.
После сохранения файл заново читается игровым API: числовые значения должны
совпасть с буфером сохранения и соответствовать состоянию с учётом штатного
округления G15. Если начисление исчезло при сериализации, успех не показывается.

Команда привязана к идентификатору, текущей игровой сессии и ревизии настроек.
Повтор идентификатора возвращает квитанцию без повторной выдачи. После потери
ответа лаунчер предлагает «Проверить результат», сохраняя тот же запрос.
Смена сессии отклоняет старую команду. За сессию хранится до 4096 квитанций;
старые не удаляются с риском повторного начисления.

## Бесплатные покупки

Пять отдельных функций в категории «Покупки», выключены по умолчанию:

- Монеты: оборудование и обычные Upgrade.GetCost; платные и сюжетные награды
  исключены. Для максимальной покупки задана конечная пачка до 100 уровней,
  чтобы нулевая стоимость не создала бесконечный цикл подбора количества.
- SP: стоимость ещё не открытых навыков обнуляется. Условия открытия сохраняются.
- DP: стоимость ещё не купленных божественностей обнуляется. При успешном
  открытии исходная стоимость компенсируется в общем DP, после чего обычный
  учёт потраченного DP сохраняет доступный баланс. Сброс может вернуть такие
  компенсированные очки; общий заработанный DP растёт.
- USP: аналогичная компенсация улучшений времени. Пожизненные USP и стоимость
  следующего очка пересчитываются. Распределение по камням времени не становится
  бесплатным отдельным действием.
- Крафт: постоянные и временные рецепты без расхода монет/материалов/DP рецепта.
  Условия открытия, требуемые предметы и другие prerequisites сохраняются.
  Пачка временного крафта ограничена 100. Это не общий запрет списания любых
  материалов во всех механиках игры (например, не заявлены отдельные операции кузницы).

Перед первым включением создаётся резервная копия. При выключении возвращаются
исходные цены; уже купленные вещи и прогресс остаются. Сохранения не откатываются.
Изолированная ошибка этого модуля отключает режимы покупок и записывается в журнал.

## Камни душ: что подтверждает локальная выдача

Код использует локальные баланс и earned, штатное сохранение и обновление UI.
Это позволяет исследовать обычное расходование локального кошелька. Проверка
локального файла или перезапуска не доказывает принятие сервером, перенос на
другое устройство, восстановление покупок или работоспособность каждого товара.
Не заявлены бесплатные реальные покупки, квитанции Steam, выдача серверных
товаров/фишек и подмена истории платежей. Отдельного переключателя «все товары
за камни бесплатно» нет: у разных товаров разные обработчики и ограничения.

## Числа, список и виджет

Множители теперь принимают конечные double от 1 (до примерно 1.797e308), включая
научную запись 1e60. Около 15–17 значащих цифр сохраняются точно; длинное целое
округляется. Переполнение произведения отклоняется с сохранением исходного
начисления. Для монет дополнительно проверяется доступный диапазон обоих
балансов. Это не обещание корректной работы всех внутренних игровых формул
у самого предела double: крайние значения требуют проверки в игре.

Размер значения double не меняет размер переменной или сложность одного
умножения. Косвенные расходы игровых событий/форматирования и фактический FPS
в текущем изменении не измерены.

Активный список строится из включённых функций каталога только при изменении
настроек. Значения форматируются через AbbreviationUtility.AbbreviateNumber
игры; научная запись остаётся запасным вариантом. Для будущих переключателей
каталог предусматривает HasMultiplier=false и состояние «вкл». Автофарм пока
не реализован и не показывается как готовая функция.

Виджет перетаскивается напрямую: начало на виджете, порог смещения, сохранение
координат после отпускания. Клик по кнопке меню остаётся отдельным действием.
Список переносится вместе с виджетом и размещается над ним у нижней границы.
Пользователь может скрыть список отдельно в обоих интерфейсах.
