Статус на 16 октября 2026: получена Android 7.3.4 (866), ARM64, Unity 6000.3.14f1.
Подписи всех пяти исходных частей проверены; создан настоящий Android Interop,
мод собран с ним без ошибок/предупреждений. Проверены 23 цели игровых патчей.
Профиль `profiles/idle-slayer-7.3.4-arm64-preview.json` разрешён **только как preview**:
`StaticApiChecked=true`, `RuntimeVerified=false`. Это не приёмка функций в игре.
Собран локальный APK (128 537 740 байт):
`W:\DEV\artifacts\DivineLabs_IdleSlayer_Mods\android-7.3.4-preview-1\DivineLabs.IdleSlayer.Android.apk`.
Подпись v2/v3, выравнивание 16 KiB, CRC ZIP, собственные DLL, native/metadata и
64 исходных игровых assets проверены. SHA256 записан рядом в SHA256SUMS.txt;
подробный отчёт — artifact-validation.json, инструкция — README.ru.txt.
На TECNO LH7n (Android 14, API 34) установка проверена, но запуск preview 1
завершается SIGSEGV в libpairipcore.so до загрузки DivineLabs. Пользователь
подтвердил работу оригинала после обновления через Google Play. Android-релиз
остаётся неподтверждённым; подробности физических прогонов — в docs/VALIDATION.md.

**Обнаружена оболочка PairIP**: `com.pairip.application.Application`,
`libpairipcore.so` и классы SignatureCheck/VMRunner присутствуют в исходной игре
и в предварительном APK. Изменение подписи/содержимого может быть отклонено
проверкой целостности до загрузки меню. На устройстве подтверждено падение
в libpairipcore.so +0x4454c; точная внутренняя причина не установлена.
Корректная APK-подпись, Interop и компиляция не подтверждают запуск.
Экспериментальные изменения загрузки не включены в штатную сборку.


## Какой продукт делаем

Вариант без обязательного root: локально подготовленная копия APK игры со встроенными
функциями и сенсорным меню DivineLabs. Отдельное обычное приложение не может менять
память другой игры из-за изоляции Android. Windows EXE, WPF, user32 и desktop-загрузчик
в APK не переносятся. Steam-запуск на Android не используется.

Сама игра, её APK/DEX/библиотеки, игровые Interop и сохранения не коммитятся и не
публикуются. Подготовленный пользовательский APK остаётся локально под W:\DEV\artifacts.

## Реализовано в исходниках

- Отдельное меню uGUI/TMP: верхние вкладки, список функций с поиском/категориями/
  избранным, настройки, разовые команды ресурсов. Крупнее элементы для сенсорного ввода.
- Открытие кнопкой виджета или касанием тремя пальцами. Один жест даёт одно
  переключение; ввод удерживается до отпускания всех пальцев. Скрытый виджет
  не отключает жест. Перетаскивание, активный список, безопасная область экрана,
  поворот, масштаб, прозрачность и уменьшение анимаций предусмотрены кодом.
  Перетаскивание закреплено за конкретным fingerId: второй палец его не перехватывает;
  отпускание после движения/отмена/жест не превращаются в нажатие меню.
  При перемещении виджет ограничен безопасной областью, включая вырезы экрана.
- Общие с Windows модели, ограничения чисел, множители, выдача и режимы покупок.
  Их работа на Windows не считается проверкой Android-версии игровых методов.
- Локальное владение JSON и квитанции команд. Windows named pipe не компилируется
  в Android; меню вызывает тот же локальный обработчик. Портов и внешнего API нет.
- Настройки: Application.persistentDataPath/DivineLabs/DivineLabs.settings.json.
  Копии ресурсов: рядом в DivineLabs.Backups/Resources. Игровые .sav читаются из
  Application.persistentDataPath. Реальное расположение проверяется по APK.
- Профиль проверяет ARM64, Android, package/versionName и SHA256 libil2cpp.so +
  metadata из фактического установленного APK до подключения игровых патчей.
  Шаблон profiles/unapproved.example.json всегда выключен. Профиль не утверждается
  автоматически по совпадению имени игры или номера версии.

Игровые методы доступны в Android Interop и прошли проверку сигнатур. Их реальное
поведение, шрифты/кириллица, клавиатура, touch routing, scene callbacks и сохранения
**не проверены из-за сбоя запуска на устройстве**. Статическая проверка
не подтверждает начисления в сессии.

## Подготовка SDK и исходника с телефона

```powershell
./scripts/android/Get-AndroidSdk.ps1
python -B ./scripts/android/collect_game.py --list-devices
python -B ./scripts/android/collect_game.py
```

SDK устанавливается в `W:\DEV\tools\android-sdk`: только Platform Tools 37.0.1
и Build Tools 37.0.0, без Android Studio, эмулятора и NDK. Архивы с официального
сервера Google закреплены по размеру/SHA256; существующие файлы сверяются с
архивом при повторном вызове. Изменённые файлы не перезаписываются автоматически.
Лицензия SDK и исходные NOTICE сохраняются рядом с инструментами; они не входят
в игровой APK. Лицензия: [Android SDK](licenses/Android-SDK-License.txt).

Подключите телефон по USB, включите USB-отладку и подтвердите разрешение на
самом телефоне. Сценарий не подтверждает его за пользователя. При нескольких
устройствах укажите `--device-index 1` по выведенному списку; серийные номера
не печатаются и не попадают в отчёт. При неоднозначном названии игры можно
указать `--package com.pabloleban.IdleSlayer` после проверки имени на телефоне.
Root для чтения установленных APK не используется.

Полученные файлы остаются в новой папке
`W:\DEV\environments\idle-slayer\android\phone-ДАТА-ВРЕМЯ`.
В `collection.json` записываются SHA256, версия/пакет, API и ABI телефона,
без аккаунтов, серийного номера и удалённых путей установки. Игра и её данные
не изменяются. Если приложение обновилось во время копирования или части имеют
разные версии, успешный отчёт не создаётся; частично скопированные файлы остаются
для диагностики. Существующие папки не перезаписываются.

Для одного полного APK дополнительно создаётся выключенный `candidate.json`.
Если Android выдаёт split-комплект, сохраняются **все** части. Для него или XAPK:

```powershell
./scripts/android/Prepare-AndroidInput.ps1 -GamePackage 'W:\DEV\environments\idle-slayer\android\phone-ДАТА-ВРЕМЯ'
```

Подготовка проверяет целостность отчёта получения, package/versionCode,
подписи **каждой** части через apksigner и совпадение их сертификатов.
APKEditor 1.4.9 (закреплён по SHA256) объединяет части; после этого сверяются
SHA256 `libil2cpp.so` и metadata с исходниками. Выход `game-arm64.apk` ещё не
подписан нашим ключом; `candidate.json` остаётся выключенным. Оригиналы сохраняются.
Наличие корректной подписи доказывает целостность подписанного содержимого,
но само по себе не удостоверяет личность владельца сертификата.
Не нужно удалять игру или заменять её ради получения файлов.

## Сборка из пользовательского APK

Загрузчик как техническая зависимость: LemonLoader v0.7.4-android.3, Patcher v2.1.0.
URL и SHA256 закреплены в dependencies.lock.json. Их происхождение и Apache-2.0
сохранены; это не собственная реализация CoreCLR/ARM64-загрузчика DivineLabs.
Документация upstream заявляет Android API 26+ / ARM64 / Unity IL2CPP; фактическую
совместимость Idle Slayer и конкретного телефона ещё нужно проверить.

1. Нужен полный APK с ARM64 `libil2cpp.so` и metadata или полный split/XAPK комплект,
   подготовленный через `Prepare-AndroidInput.ps1`. Один base.apk недостаточен.
   Готовый сторонний мод не используем как исходник.
2. scripts/android/inspect_apk.py читает бинарный AndroidManifest, ABI/ELF и hashes,
   не распаковывая APK и не меняя его. Выход — выключенный кандидат профиля.
3. После анализа именно Android-сборки сохраняется отдельный утверждённый профиль
   в profiles (только сведения о сборке) либо локальном android/private. Нужны реальные
   package/versionName/native/metadata hashes. `ApiReview` проверяет найденные
   по имени цели патчей, компиляция — типизированные обращения. RuntimeVerified
   отмечается отдельно; профиль preview не считается подтверждённым на устройстве.
4. scripts/android/Build-Android.ps1 проверяет профиль, согласует minSdk >=26 и
   оставляет ARM64-библиотеки, генерирует Interop из этого APK и собирает AndroidMod
   на net10.0 с Android-загрузчиком. Подстановка Steam DLL в этом сценарии отсутствует.
5. Patcher добавляет только Loader/наши модули, выравнивает APK под 16 KiB и подписывает.
   Отдельные apksigner verify и zipalign проверяют подпись и выравнивание.
   Упаковка проверяет, что libil2cpp/metadata сохранились, а собственные DLL совпадают
   с созданными. Все операции создают новую папку, исходный APK не перезаписывается.

Нужны PowerShell 7.4+, .NET 10 SDK, Python 3.11+, Android SDK Build Tools и постоянный
keystore. Пароль задаётся через LEMONLOADER_KEYSTORE_PASSWORD (при необходимости
также LEMONLOADER_KEY_PASSWORD) либо защищённый DPAPI-файл ниже. Пароли не передаются в командной строке и не печатаются.
Сертификат/ключ сохраняются для будущих обновлений, не входят в Git/дистрибутив.

`New-AndroidSigningKey.ps1` создаёт постоянный PKCS12 ключ под `W:\DEV\.state\signing`
и случайный пароль, зашифрованный Windows DPAPI текущего пользователя. Существующие
файлы не перезаписываются. `Build-Android.ps1` читает защищённый пароль, если
переменная окружения не задана. Пароль/ключ не печатаются. DPAPI-файл привязан
к этому пользователю Windows; при переносе ключа пароль нужно перенести отдельно
защищённым способом. Сам SDK и ключи уже подготовлены на текущем компьютере.

```powershell
python -B ./scripts/android/inspect_apk.py 'W:\DEV\environments\idle-slayer\android\original.apk' --output 'W:\DEV\environments\idle-slayer\android\candidate.json'

./scripts/android/Build-Android.ps1 -GameApk 'W:\DEV\environments\idle-slayer\android\original.apk' -CompatibilityProfile './android/profiles/idle-slayer-7.3.4-arm64-preview.json' -DeviceApi 34
```

DeviceApi здесь пример: задайте реальный API телефона, если он известен.
До первого вызова сборки нужен проверенный вход и постоянный ключ подписи. По умолчанию используются закреплённые Build Tools 37.0.0.
Сценарий не устанавливает APK на телефон, не удаляет
приложения, не трогает их данные и не подменяет платёжные/облачные проверки.

Подпись локального APK отличается от подписи издателя: обновить оригинальную
установку поверх неё обычно нельзя. Не удаляйте игру и не очищайте данные ради
пробы: сначала проверяется сохранение прогресса и способ безопасной установки.
Проверка переносимости облака/аккаунта и магазинных покупок — отдельная часть
испытаний; работа на Steam этого не подтверждает.

## Что проверено

- Статический `audit_runtime.py` на текущем APK: payload формата 9 / android-arm64,
  наличие обязательных Loader/Interop/своих модулей и согласованность deployment.
  Все 33 `.so`, включая извлекаемый приватный .NET runtime, имеют ARM64 ELF LOAD
  с выравниванием минимум 16 KiB и согласованными смещениями. Проверка не подменяет
  запуск на физическом устройстве 16 KiB. Сырые границы RELRO записаны для
  диагностики; по одному их смещению вердикт о совместимости не делается.
- 7 новых проверок native-аудита: корректный ELF/информационный RELRO, 4 KiB/
  несогласованное/неверное выравнивание, усечённая таблица, другая архитектура,
  ApplicationClass в UTF-8/UTF-16/plain XML, обнаружение PairIP и неполный payload.
  Всего Python: 32 проверки. `runtime-audit.json` находится рядом с APK.
- Полная Build-Android.ps1 из объединённого входа: новая генерация Android Interop,
  ApiReview, компиляция Mod/Contracts, внедрение Loader, подпись v2/v3, проверка
  подписи/16 KiB выравнивания и hashes модулей прошли. Финальный CRC ZIP и все
  64 оригинальных assets совпали; native/metadata также сохранены.
- Подготовка реального XAPK 7.3.4 (866), все пять подписей и одинаковый SHA256
  сертификата, сохранение native/metadata после слияния. Исходник получен с APKPure,
  а не с пользовательского телефона; сопоставление с его установкой не проводилось.
- Cpp2IL и Il2CppInterop создали 153 Android-сборки из ARM64 ELF/metadata 39;
  AndroidMod собран с ними без предупреждений. Статический ApiReview: 23 цели.
- 7 дополнительных проверок staging split APK: сохранение исходника/байтов,
  объявленные отсутствующие части, смешанные версии, дубли native, опасные ZIP-пути,
  изменение копии с телефона и отказ от перезаписи. Всего Python: 25 проверок.
- 17 проверок логики касаний без Unity/телефона: владение fingerId, чужой палец,
  порог движения, тап/перетаскивание, отмена, смена сцены и жест тремя пальцами
  с частичным отпусканием. `dotnet run --project tests/AndroidInput -c Release`.
  Мобильный мод после изменения собран без предупреждений с Android Loader и
  диагностическими Steam Unity-прокси; это не проверка uGUI на телефоне.
- ADB 37.0.1, apksigner и zipalign запускаются из локального SDK. Повторная
  проверка всех файлов SDK по закреплённым архивам прошла. ADB: телефон не обнаружен.
- 8 проверок сборщика исходников на имитации ADB: полный APK, все split-части,
  hashes/выключенный профиль, смена версии при копировании, чужой пакет/смешанные
  версии, сохранение прежних файлов, некорректные пути/параметры, отсутствие
  авторизации и неоднозначный выбор устройства. Физический телефон не использовался.
- 10 проверок синтетических APK: UTF-8/UTF-16 binary XML, ABI, hashes, отсутствие
  изменения исходника, minSdk/ARM64 подготовка, регистр путей, дубль/обход ZIP,
  уже внедрённый Loader, нестандартная metadata, повреждённые границы manifest.
  Это непригодные для установки фикстуры, не игровые APK.
- Проверка компиляции сенсорного кода с настоящими библиотеками Android Loader:
  успешно без предупреждений. Для типов Unity использованы локальные Steam-прокси,
  поэтому полученные диагностические DLL **не являются Android-поставкой**. Профиль выключен.
  Воспроизведение: scripts/android/Check-Compile.ps1. Выход только в .cache/temp.
- В собственных Android-сборках проверено отсутствие System.IO.Pipes и
  Windows P/Invoke. Windows Mod после условного разделения также собирается.
- Проверен синтаксис PowerShell и фактические CLI options Patcher 2.1.0.

Не проверены: принятие изменённой сборки проверками PairIP, запуск Android/установка,
мобильные методы начисления/расходов и сохранения, JNI/Unity hooks, сенсорный ввод,
ориентация/клавиатура/кириллица, нагрузка и облако. Стабильный релиз не заявляется.

## Ручной CI-прогон запуска

`.github/workflows/android-startup.yml` запускается только через workflow_dispatch.
Он использует отдельный GitHub Linux runner, Android 11 x86_64 с ARM64 translation
и KVM; не меняет BIOS/установку на пользовательском телефоне. На удалённом runner
временные файлы находятся в RUNNER_TEMP, локальные исходники/артефакты — под W:\DEV.

CI повторяет подготовку проверенных оригинальных частей и Android Interop,
проверяет код и собирает отдельный тестовый APK. Ключ генерируется одноразово
внутри job; локальный постоянный ключ и аккаунтные данные не передаются.
**Это не побайтово тот же APK**, который лежит на пользовательском компьютере.
Проверяется старт процесса/инициализация мода; работа меню и начислений этим
не подтверждается. Физическое ARM64-устройство остаётся отдельной проверкой.

Публикуется только android-startup-report (JSON, отфильтрованный журнал и снимок
нового виртуального устройства без аккаунтов). APK, оригинальная игра, Interop,
сырые журналы и ключи не загружаются в GitHub artifacts/releases/cache.
Все внешние Actions закреплены по SHA, job имеет только contents:read.

### Физический телефон: результат первого запуска

16 октября 2026 выполнена установка preview 1 на TECNO LH7n, Android 14 / API 34,
ARM64. Пользователь разрешил удаление прежней игры с ненужным прогрессом.
